# EUI Click Trace

Temporary, standalone diagnostics for intermittent priest click-casting failures.
The addon observes global mouse events and player spell events. It does not hook
secure buttons, modify attributes, change bindings, inspect aura contents, or cast
spells. `.tools` is excluded from the EllesmereUI release package.

Open [the offline instance checklist](instance-checklist.html) for activation,
incident marking, recovery tests, and the results template.

## Use in game

1. Install the `EUIClickTrace` directory in Retail `Interface/AddOns`, then fully
   restart WoW. Existing EllesmereUI files and settings do not need replacement.
2. Run `/euict status`. It should show ON and zero observer errors. Click-cast a
   normal heal and check that the event count increases.
3. When casting fails, run `/euict mark tank stuck` as soon as safely possible.
   A normal macro containing that command can be placed on an action bar and
   activated by a spare keyboard binding. It only marks the log.
4. Continue testing recovery: hover another frame without casting, then try
   normal targeted Flash Heal, then try casting on another player. Optional
   further markers can label those steps, but wait 20 seconds between markers
   if the previous marker needs its full following window.
5. After the run, `/reload` or log out normally to write the log to disk. Tell the
   investigator the marker label, approximate time, spec, and observed recovery.

`/euict off` pauses collection and retains evidence. `/euict on` resumes it.
No chat, player names, GUIDs, macros, or aura lists are intentionally collected.
UI error text and spell names may appear if WoW makes them available.

## Evidence and limits

SavedVariables file: `WTF/Account/<account>/SavedVariables/EUIClickTrace.lua`.
WoW writes it on a normal logout, exit, or reload, not continuously. A crash can
lose unsaved events. Do not edit this file while WoW is running.

The schema version is `1.0.0`. `current` and `previous` retain two sessions, each
with a 3,000-row circular buffer. `next` is the newest slot and `count` is the
occupied count. Chronological slot `n` (1-based) is
`(next - count + n - 1) % 3000 + 1`. Each row has a monotonic `t`, `event`,
sanitized `details`, and optional `state`. Session `wallTime` and
`monotonicStart` allow approximate wall-clock conversion.

Up to eight marked incidents survive reloads. Each holds up to 500 preceding
events from the previous 60 seconds and 300 following events over 20 seconds,
including the marker. High input rates may shorten the effective time window.
A new marker ends the previous following window. Full incidents evict oldest
first. No per-frame polling or combat-log stream is enabled.

Mouse rows include down/up button, modifiers, casting/channeling/targeting state,
mouseover/target existence, friendly/dead/role state, Flash Heal usability/range,
and up to three focus-frame ancestry chains of six entries each. Frame reads
include name/type, mouse-click/motion state, unit, and unmodified type1/type2.
Actual macro text is not collected. Spell events omit SENT's target-name field.
UI errors record their ID and sanitized text.

`<restricted>`, `<denied>`, and `<unavailable>` distinguish inaccessible values.
Forbidden focus frames are not inspected. `observerErrors` counts unexpected
logger errors that are contained by the event wrapper; `unavailableEvents`
lists rejected registrations. Nonzero counts require investigation before
relying on missing events. Global mouse timestamps do not prove delivery to a
secure button or macro execution, and absent spell events do not prove failure
if the engine withholds them. A forbidden focus record may hide the overlay.

## Validation and removal

Run `python test_clicktrace.py` with `lupa` installed. The tests execute the addon
under Lua 5.1 with mocked WoW APIs. They cover bounded retention, spell argument
positions, player scoping, missing mouseover, restricted/denied/forbidden reads,
marker windows, pause/reload retention, and observer-error containment. Actual
event availability and combat behavior still need the in-game smoke check.

Disable EUI Click Trace in the AddOns list when investigation is complete.
Removing its standalone folder uninstalls it without touching EllesmereUI.
Keep its SavedVariables file until the incidents have been inspected.
